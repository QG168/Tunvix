# 缩略图并发与稳定显示

日期：2026-10-07。状态：代码已实现并验证；本轮版本仍为 0.1.1 / versionCode 2，未打包、未替换交付 APK、未操作手机。

## 问题与方案

旧版自动截图为单并发，手动刷新串行，每频道最长 10 秒；磁盘超过 24 MiB 会淘汰图片。卡片移出屏幕释放 Compose 显示状态，回来重新异步解码，期间出现占位。上述分别属于抓取队列、磁盘保存和前端显示问题。

当前自动与手动共享 3 个抓取名额，最多使用 3 个工作协程处理各自队列，不为整个分组创建大量逐频道协程。每频道拿到名额后开始计时，格式识别和 HLS 回退共用 8 秒。超时或异常只让当前频道失败，关闭 FrameExtractor 后继续处理下一项。

自动只补缺失截图，保留失败冷却；同一批中每频道只尝试一次，避免大量无效源导致冷却表容量耗尽后循环重试。手动刷新先取消并等待自动任务退出，再并行重抓；所有任务结束后反馈成功/失败数量。进入播放、后台或切换分组/源取消任务，取消完成不遗留解码名额。

## 持久保存

生产目录由 cacheDir/thumbnails 改为 filesDir/thumbnails，读取时迁移仍存在的旧图，保留文件名和目录引用。迁移失败保留可读取的旧文件、下次启动重试，不因为图片迁移失败阻止目录使用。已经被旧版本淘汰或系统清除的图无法恢复，按缺图处理。

图片保持最大 320×180、JPEG 质量 65。移除 24 MiB 磁盘淘汰，截图内容不因滑动、切分组或重启改变。更新订阅时仅让 URL / 请求头变化的频道失效；其余保留。

新截图和目录保存成功后才删除旧图；抓取、编辑、删除和清理的目录保存失败都保留旧截图。每频道保留当前一张，删除源/频道或主动清理时删除，启动清理无引用文件。源、收藏和观看记录不受截图清理影响。

## 稳定显示与内存

应用级 SharedImageCache 按完整 URI 管理 12 MiB 的 LRU 解码缓存；同 URI 同时读取合并为一次解码，卡片销毁只取消自身等待，不取消其他卡片共享的加载。

卡片重入屏幕时同步显示已缓存图片；刷新加载新 URI 时保留现有图，加载成功才替换。频道身份使用独立显示状态，媒体变化导致截图失效或用户主动清理时清除旧图，避免串台。内存淘汰只释放缓存引用，不删磁盘截图、不重新抓视频；淘汰后再次显示需要从磁盘解码。

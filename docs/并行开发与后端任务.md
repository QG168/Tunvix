# Tunvix 并行开发与后端任务

版本：v1 · 2026-10-07

首版是本地安卓 App，不需要远程服务。这里的“后端”指导入解析、本地持久化、播放器及缓存能力。用户分别启动三个对话，我在当前对话负责原生 UI；不要由其他对话重写 UI。

## 公共依据与接口

- 产品：`docs/Tunvix-PRD.md`。
- 视觉：根目录 `Tunvix 完整界面设计稿.html`；仅前端负责还原。
- 固定接口：`core/contract/src/main/kotlin/com/tunvix/contract/Contracts.kt`。以实际 Kotlin 声明为准。
- 根工程已有 `:app`、`:core:contract`；检测到对应 build 文件时自动包含 `:backend:importer`、`:backend:catalog`、`:backend:playback`。
- 后端模块均为 Android library，`compileSdk=37`、`minSdk=29`，依赖 `project(":core:contract")`；复用根工程插件版本，不单独升级工具链。
- 前端由 `AppServices` 装配 `CatalogRepository`、`SourceImporter`、`PlaybackController`；第一阶段 demo 使用内存适配器，live 初始为空。不把样例频道打包到正式数据层。
- UI 独立构建使用 `-PuiOnly=true`，不加载施工中的后端模块；后端对话构建自己的模块时不要添加此参数。
- 所有网络、文件和数据库工作在后台线程执行；用 `Outcome.Failure` 返回可展示错误，不吞掉协程取消。
- `StateFlow` 发布不可变快照；ID 是关联依据，不能使用源名或频道名作为唯一 ID。

## 文件边界与并行规则

| 负责人 | 可写范围 | 对其他模块的依赖 |
| --- | --- | --- |
| 当前前端对话 | `app/`、公共契约、根构建与 UI 文档 | 契约 |
| 对话 A：导入 | `backend/importer/`、`docs/backend-importer.md` | 契约 |
| 对话 B：本地数据 | `backend/catalog/`、`docs/backend-catalog.md` | 契约；构造函数注入 SourceImporter |
| 对话 C：播放 | `backend/playback/`、`docs/backend-playback.md` | 契约 |

- 在同一目录工作时只改自己的范围，不重置、不清理、不提交其他人的文件。
- 不修改 `app/`、根 Gradle、公共接口和其他模块。接口不够用时记录提案，由前端统一调整。
- 避免共同编辑 PRD；各自在自己的交付文档记录进展。
- 各模块独立构建、测试，完成后报告公开入口、依赖、验证和限制。
- 可以同时开工。B 通过接口注入 A，先用测试实现，不等待 A 完成；前端最后集中装配。

## 对话 A：直播源导入模块（可直接复制任务）

请在 `/Users/long/Desktop/程序开发/Tunvix` 开发 `backend/importer`，只修改该模块及 `docs/backend-importer.md`。先读取 PRD、并行任务文档和 Contracts.kt。

实现 `SourceImporter`，公开入口 `com.tunvix.backend.importer.AndroidSourceImporter(context: Context)`，不负责存储或 UI。

必须完成：

1. HTTPS/HTTP 订阅下载、重定向、可取消请求、超时、大小限制及错误区分；不能把 404/403 的 HTML 当列表。
2. ContentResolver 读取系统选择的本地 URI，不读取任意路径，不需要全盘存储权限。
3. 扩展 M3U 的 EXTINF、分组、台标、tvg-id、User-Agent、Referer、EXTVLCOPT；忽略未知注释。频道地址查询参数保留完整。
4. TXT 支持 `频道名,URL` 与 `分组名,#genre#` 常见形式。UTF-8 BOM、CRLF、中文和必要编码回退需有测试。
5. 区分单个 HLS 分片清单与频道列表；返回提示用户手动添加，不导入每个分片为频道。
6. 部分无效返回跳过数，零有效频道返回失败；报告频道和分组数量，不访问每个频道验证播放。
7. 测试字段顺序、逗号名称、未知标记、非媒体后缀、重复项、错误网页与取消；固定样本脱敏。

不要实现绕过服务器验证或无限重试。不要内置给定的公共订阅。提交交付文档，注明支持格式、编码、限制和测试命令。

## 对话 B：本地数据与截图缓存（可直接复制任务）

请在同一项目开发 `backend/catalog`，只修改该模块及 `docs/backend-catalog.md`。先读取 PRD、并行任务文档和 Contracts.kt。

实现 `CatalogRepository`，公开入口 `com.tunvix.backend.catalog.LocalCatalogRepository(context: Context, importer: SourceImporter)`。仅通过 SourceImporter 接口使用导入模块，不依赖它的实现包。

必须完成：

1. 源、频道、收藏、最近观看和设置的本地持久化；全新安装没有示例频道，保留空的自建频道。
2. 多源手动选择、导入提交、重导入、手动刷新、修改源、自建频道增删改。
3. 刷新成功原子替换，失败旧数据完整保留；源内稳定频道匹配不能仅靠易过期 URL，同名跨源不合并。
4. 收藏和最近关联频道 ID；最近去重并按时间排序；删除源清理关联数据，禁止删除自建源本身。
5. UI 选择文件后持久 URI 访问权限由前端获取，数据层保留 URI 并处理授权失效。
6. `requestThumbnails` 按可见 ID、网络许可和有限并发执行，返回快照中的本地缩略图 URI；支持取消和缓存清理，清缓存不清个人记录。
7. 截图不能与主播放器争抢资源，前端只在非播放状态申请。无法截帧必须回退，不能卡住浏览。缓存和历史上限写入交付文档。
8. 测试刷新失败、删除隔离、跨源同名、URL token 改变、重复导入、持久化重启和设置。

截图提取可由 Android 平台媒体能力或 Media3 实现，不把截图任务委托给主播放控制器。不实现服务器。数据库和缓存迁移策略记录清楚。

## 对话 C：播放器与系统音量（可直接复制任务）

请在同一项目开发 `backend/playback`，只修改该模块及 `docs/backend-playback.md`。先读取 PRD、并行任务文档和 Contracts.kt。

实现 `PlaybackController`，公开入口 `com.tunvix.backend.playback.Media3PlaybackController(context: Context)`。不负责 Compose UI、频道数据库或上下台顺序。

必须完成：

1. Media3/ExoPlayer 播放 HTTP/HTTPS HLS 和常见渐进式媒体地址，保留每频道 headers；不仅凭后缀选择格式。
2. attachSurface/detachSurface 绑定 UI 创建的 SurfaceView，重绑定不重建播放器、不重连；等比适配视频输出，更新真实视频比例。
3. 发布连接、播放、暂停、失败状态，清楚区分失败原因；暂时断流有限重试，绝不自动切台。
4. 快速切台旧请求不可覆盖新频道状态；retry 针对当前频道。
5. 返回 stop，后台停止拉流，前台回到直播位置；明确记住用户主动暂停与后台暂停。
6. AudioManager 控制媒体流，百分比映射真实档位，侧键变化时刷新快照；处理音频焦点和耳机断开。
7. stop/release 生命周期正确，避免释放后回调和 Surface 泄漏。
8. 测试状态切换、旧回调、重试限制与音量边界；真机验证音量同步和横竖屏 Surface 重绑定。

本模块不能添加后台播放服务、画中画、遥控 UI 或数据库。缺少协议支持时清晰返回错误，不声称所有直播源都能播放。错误日志隐藏 token。

## 最后集成

三个后端对话交付后由当前前端对话统一完成：

1. 添加 app 的模块依赖，在 live 的 AppServices 工厂连接三个公开入口，并设置 `backendReady=true`；该开关表示可以使用真实播放，不代表来源可信。
2. 联调导入 → 保存 → 浏览 → 播放 → 收藏/最近 → 刷新/删除。
3. 验证 Wi-Fi/移动网络、生命周期、切台、音量、Surface 重绑定和缓存策略。
4. demo 仍保留为独立包名的视觉验收版本；live 包绝不含演示频道。
5. 小米 14 与 Android 10 验收，输出正式测试 APK 和已知限制。

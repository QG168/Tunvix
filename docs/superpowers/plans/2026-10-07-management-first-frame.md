# Tunvix 首页精简、管理入口与首帧耗时 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 精简首页，将直播源选择、添加与应用设置统一到第四个底栏“管理”，并提供可关闭的首帧耗时显示。

**Architecture:** 沿用 Compose 页面、TunvixModel 和本地目录仓库。增加管理一级页，复用现有直播源操作与设置内容；检测复用已有 3 并发抓帧调度，不增加独立解码池。

**Tech Stack:** Kotlin、Jetpack Compose、Media3 FrameExtractor、本地目录持久化。

**Spec:** 本文“确认的界面与行为”记录用户已确认的最新需求；基础需求见 ../../Tunvix-PRD.md。

## 确认的界面与行为

### 首页

- 底栏为“频道｜收藏｜最近｜管理”。管理采用 24×24、1.8 线宽的调节线框图标；已准备 SVG 原稿 `design/manage.svg`、安卓矢量 `app/src/main/res/drawable/ic_manage.xml` 及 `Glyph.MANAGE`，后续接入底栏，选中／未选中颜色复用现有底栏主题。
- 顶部左侧为 Tunvix 品牌字样，右侧搜索和截图刷新并排；两按钮使用一致尺寸，不增加顶部高度。
- Tunvix 下方显示当前源名称的小字，位于同一顶部区域内，不另外占一整排。名称单行省略，不可点击；无源时显示“未选择直播源”。
- 移除首页原来的源选择卡片，以及右上角源管理按钮。首页不再通过弹出列表切换源。
- 顶部之后直接接频道分组，再接双列频道卡片；保留现有卡片尺寸与 16:9 比例，内容整体上移。
- 搜索继续使用现有展开式搜索区域；关闭搜索恢复上述顶部。搜索不改变当前源、分组或切台顺序。
- 刷新仍只更新当前分组截图，不刷新订阅列表；开启耗时显示时同批更新检测结果。搜索过滤不缩小整个分组的刷新范围。
- 无源或当前源无频道时刷新不可操作。空首页保留添加直播源主按钮，跳转到管理入口所属的添加流程。

### 管理一级页

- 保留底栏，当前项“管理”高亮；一级标题“管理”不提供返回箭头。
- 上半部分为“直播源”，标题右侧是“＋ 添加”，打开现有订阅链接／本地文件／手动频道选择页面。
- 已有源按目录顺序预览前 3 个；选中的源不在这 3 个内时，额外显示当前源，避免重复。超过 3 个源时提供“查看全部直播源”进入完整列表。
- 每个源带单选标记，当前源显示蓝紫色勾选；点击卡片主体或勾选区立即切换当前源。切换成功继续留在管理页，用户点“频道”查看它的频道。
- 刷新订阅、编辑和删除按钮独立响应，点击这些按钮不触发源切换。选择保存失败时保留原选中项并提示失败。
- 无源时显示简洁添加卡片，应用设置仍正常展示。自建源按现有规则首次保存手动频道才出现，可以删除。
- 下半部分直接显示应用设置，顺序为：移动网络播放提醒、按键震动反馈、显示首帧耗时、截图存储、清空观看记录、关于 Tunvix。
- 已有设置能力复用，取消源管理右上角的设置入口；设置不再需要单独进入一页。截图清理文案同步说明 Wi-Fi/移动网络均可补图。

### 页面返回

- 添加、全部直播源、编辑和关于等二级页隐藏底栏，返回所属入口。
- 从管理进入添加后，取消返回管理；从首页空态直接添加后，取消返回首页。
- “全部直播源”选中源后保留在列表，返回管理。该列表的添加／编辑返回它自身。
- 导入成功进入频道首页并显示新选中源；失败保留表单或结果页以便重试。
- 不用“返回首页”作为所有二级页面的固定返回方式，记录实际入口。

### 首帧耗时设置与标签

- 开关名“显示首帧耗时”，默认关闭并持久保存。
- 说明：“检测需要请求直播源，显示最近一次测量结果。”
- 开启后，频道、收藏、最近的缩略图右下角显示半透明深色、小圆角标签；数值用按耗时分档着色的小字带单位，例如“860 ms”，不使用会拉伸卡片的额外行。
- 未检测为“—”，正在检测为“…”，超时为“超时”，其他失败为“失败”；不能把失败显示成 0。
- 首帧耗时是从发起媒体请求到取得第一张可解码画面的时间，包含连接、读取和解码，不含排队等待及 JPEG 压缩。用于比较打开速度，不称作画面相对现场的直播延迟。

### 标签颜色分档

保持统一半透明深色背景，仅改变数字、单位或状态文字的颜色，不给整块标签填充绿／黄／红色，也不改变卡片尺寸。颜色辅助判断，数值、单位与状态文字始终保留。

| 结果 | 文字颜色 | 含义 |
| --- | --- | --- |
| 成功且耗时 ≤ 1000 ms | 柔和绿色 | 打开较快 |
| 成功且 1000 ms < 耗时 ≤ 3000 ms | 暖黄色 | 需要稍等 |
| 成功且耗时 > 3000 ms | 柔和红色 | 打开较慢 |
| 达到 8 秒总超时，未取得画面 | 红色“超时” | 本次未取得画面 |
| 其他检测失败 | 红色“失败” | 本次检测失败 |
| 未检测／检测中 | 灰色“—”／“…” | 暂无结果 |

分档使用测量的毫秒值，不能先四舍五入成秒再分档；1000 ms 属于绿色，3000 ms 属于黄色。超时／失败依照任务结果判断，不能仅因数值变红就标为失败。示例：100 ms、860 ms 绿色；1800 ms 黄色；4200 ms 红色。

这组阈值是第一版的体验分档，不作为网络 Ping、实际直播延迟或播放流畅度的保证；后续根据小米 14 实际测量再调整。


### 检测时机与保存

- 采用“首次检测＋手动更新”：首页处理当前分组，收藏／最近处理当前展示集合。
- 同一播放地址与请求头已有结果则复用；上下滑动、切分组、重启不重复检测。失败和超时也属于最近一次结果，不定时自动重测。
- 新频道抓图复用同一次抓流测量；已有截图且无测量结果时仅检测，保留原截图，不因检测改变截图内容。
- 首页手动刷新同时更新截图与测量；失败保留旧截图，标签记录本次超时或失败。
- 结果与测量时间持久保存，播放地址或请求头变化后失效；删除频道／源同步删除。关闭开关隐藏标签、停止额外检测，但保留结果，重新开启可复用。
- 截图清理仅清除图片，不清除耗时测量结果；首次取得新图不自动覆盖已有结果，只有手动刷新或媒体变化重新测量。
- 检测与截图共享全局 3 个名额、单频道 8 秒总超时，不额外创建解码池；播放页和后台取消。关闭检测只取消纯检测任务，缺失截图的正常补图仍可继续。
- Wi-Fi 和移动网络均可检测，默认关闭避免未开启时产生检测专用请求。

## Review Focus

- 源很多且选中项在预览之外时，仍能识别当前源，单选唯一。
- 点源刷新／编辑／删除不能顺带切换源，失败不能发布未保存的选中状态。
- 不同添加入口、编辑与关于页面返回正确，导入成功保持现有首页行为。
- 已有截图只测耗时不能改变图，缺少时间数据不能伪造数值。
- 原有截图任务与新检测共享名额，取消、关开关和后台切换不留下资源占用。

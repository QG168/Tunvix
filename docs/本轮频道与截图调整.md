# 频道与截图调整

用户要求（2026-10-07）：自建源首次手动保存才创建、可以删除；首页刷新当前分组截图，订阅管理刷新订阅；移动网络/Wi-Fi 均抓取整个当前分组；图片缩小、串行解码；订阅刷新旋转并以小消息反馈；播放页去除 LIVE 标记、顶部恢复浅色；全局圆角点击波纹裁剪。

实现约束：不操作用户手机进行测试；只执行构建和有必要的模块回归。抓帧失败保留旧截图/占位，进入播放及后台停止截图；不把 logo 当作已成功抓取的直播画面。旧版本无频道的默认自建源迁移移除，有用户频道的自建源保留。

## 源码实现

- 首次安装目录为空，第一次保存手动频道时创建自建源；源管理允许删除自建源并清理其频道、收藏、历史与缓存。读取旧目录时仅移除无频道的默认自建源，有手动频道的数据保留；被移除源若原来选中则改选现存源。
- 首页刷新图标改为“刷新当前分组画面”，手动重抓已缓存截图；失败保留旧图，部分失败显示成功数量。源管理刷新保留订阅更新职责，点击后旋转、禁用重复点击、结束显示轻量消息。
- `design/refresh.svg` 保存可编辑 SVG 原稿，Android 使用同路径的 VectorDrawable，24×24 正方形 viewBox，等比例绘制。
- 当前分组所有频道均排入自动抓帧队列，允许移动网络和 Wi-Fi；搜索不缩小当前分组抓帧范围。超出旧 48 项队列限制的频道继续依次补入，不再丢弃。
- 抓帧改为 Media3 FrameExtractor，包含 HLS 模块、无后缀链接 HLS 回退、请求头传递，单个解码任务抓一帧后关闭。无法连接、受限或解码失败时继续下一频道，UI 可回退 logo/占位，但不把 logo 计为抓帧成功。
- 画面最大 320×180，JPEG 质量 65；存盘上限 24MiB，启动也执行淘汰。界面图片解码缩小至 480×270 范围，避免大 logo 常驻内存。磁盘上限与图片解码内存不同，解码器仍会短暂分配视频帧缓冲。
- 重抓成功使用新的缓存 URI，确保卡片重新加载；目录持久化成功后才删除旧图。进入播放、切换分组/源或进入后台取消批次，不让截图任务持续占用主播放器。
- 播放页去掉红点与 LIVE 标签，顶部频道名/返回/收藏改为浅色主题；视频区域保持黑色承托。圆角波纹修复覆盖源选择、添加选项、文件选择、分组选择、播放器页签、频道列表、上下台、错误按钮、弹窗按钮及演示索引。

## 验证与交付约束

新建/删除源、旧目录迁移、超过 48 个频道的顺序抓取、强制刷新及失败保留、订阅刷新反馈、播放时取消抓图、移动网络和搜索条件下整组抓图均有回归覆盖。最终命令：

```sh
./gradlew :backend:catalog:testDebugUnitTest :app:testLiveDebugUnitTest :app:testDemoDebugUnitTest :app:lintLiveDebug
```

按用户明确要求，本轮不执行 assemble/package APK、不更新交付 APK、不发送手机安装包。新增实际 HLS 画面提取和界面视觉效果等待后续统一打包，由用户真机验收。

参考：[Media3 抓帧 API](https://developer.android.com/media/media3/inspector/extract-frames)。

最终源码验证：catalog 51 项、live UI 22 项、demo UI 22 项，共 95 项单测通过；live lint 通过，git diff --check 通过。缓存淘汰后的同一批次不重复抓取，避免大分组超过缓存上限时无限循环。本轮未生成或替换 APK。

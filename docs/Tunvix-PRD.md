## 1. 产品目标

Tunvix 是以竖屏使用为主的安卓直播播放器。用户自行导入直播源，通过频道截图浏览、分组切台和简洁的遥控器面板观看直播。

首版目标是让用户在小米 14 上完成“添加直播源 → 找到频道 → 观看 → 切台 → 收藏或再次观看”的完整流程。App 不内置直播源，不要求注册登录。

### 1.1 设备与交付

- 最低支持 Android 10（API 29）。
- 小米 14 为优先适配与验收设备，小米手机重点验证澎湃 OS 1 及以上。
- Android 版本和澎湃 OS 版本分别记录、验证。
- 界面根据可用屏幕空间自适应，不按小米 14 的物理像素写死布局。
- 首版交付可自行安装的 APK，不包含应用商店发布流程。

### 1.2 首版范围

| 功能 | 首版要求 |
| --- | --- |
| 直播源 | 订阅链接、本地文件、手动频道；多源独立管理和手动切换 |
| 浏览 | 双列截图、频道分组、搜索 |
| 播放 | 竖屏、手动横屏全屏、播放状态与失败重试 |
| 遥控器 | 当前分组循环切台、手机媒体音量控制 |
| 个人记录 | 收藏、最近观看 |
| 设置 | 截图缓存、移动网络提醒、震动开关、清空历史、版本号 |

首版不包含节目单、回看、画中画、首页小播放器、持续后台播放、广告、付费和主题切换。参考图或订阅携带的相关字段不自动扩大功能范围。

## 2. 信息架构与核心流程

### 2.1 页面结构

- 主界面底栏：频道、收藏、最近、管理。
- 频道页顶部：左侧 Tunvix 品牌字样，下方小字显示当前源名（不可点击，无源显示“未选择直播源”）；右侧搜索与分组截图刷新并排。
- 管理页（一级页）：上半部分为直播源预览（按目录顺序前 3 个，额外展示不在预览内的当前源），单选切换当前源，提供“＋ 添加”与“查看全部直播源”；下半部分直接内嵌应用设置。
- 全部直播源（二级页）：完整列表，添加、编辑、删除、刷新或重新导入。
- 添加入口：订阅链接、本地文件、手动频道。
- 播放页：视频区域 + 频道／遥控器双面板；可手动进入横屏全屏。

添加、全部直播源、编辑和关于等二级页隐藏底栏，返回所属入口；导入成功进入频道首页。首页不再提供源切换弹层，空首页保留添加直播源主按钮。

### 2.2 核心流程

1. 首次使用：空首页 → 添加直播源 → 解析与结果确认 → 频道首页。
2. 日常观看：选直播源 → 选分组或搜索 → 点击频道 → 播放 → 列表切台或遥控器切台。
3. 快速找回：收藏／最近 → 点击频道 → 播放，使用频道所属源与分组作为切台上下文。
4. 订阅维护：手动刷新当前源 → 成功替换列表并匹配个人记录，失败保留原数据。

## 3. 界面设计规范

### 3.1 视觉方向

已确认采用“清爽活力”：浅灰白背景、深色文字、蓝紫强调色，年轻、轻盈、符合现代审美。

- 频道画面是视觉重点，使用适度圆角、清晰图标、充足留白与轻微阴影。
- 蓝紫色用于主要操作、选中、收藏和加载状态；避免过量渐变与装饰。
- 中文文字清晰易读，标题、正文和辅助信息层级明确。
- 操作动效短促柔和，按键可提供轻微缩放和可关闭的震动反馈。
- 不采用复古拟物、金属纹理、铭牌、实体按键、复古灯光或厚重立体效果。
- 首版固定该主题。精确色值、字体、圆角、间距和动效由后续视觉设计统一确定。

### 3.2 系统栏与可用区域

- 使用安卓状态栏和手势导航条，背景自然延伸到系统栏区域。
- 顶部状态栏图标与背景保持足够对比，播放区域使用深色背景。
- 文字与交互控件避开摄像头、系统栏和手势区域。
- 不通过隐藏手势条或写死系统栏高度来实现融合。
- 优先实测小米 14；其他屏幕、字体放大及三键导航不得遮挡主要操作。

### 3.3 页面要求

| 页面／区域 | 需求 |
| --- | --- |
| 首页第一行 | 左侧 Tunvix 文字标识，右侧搜索和源管理图标 |
| 首页第二行 | 当前源名称、下拉切换；在线订阅显示刷新按钮 |
| 分组栏 | 横向滚动圆角标签，当前分组有蓝紫选中状态 |
| 频道卡片 | 一行两个，16:9 静态截图，下方频道名称；长名称截断，卡片尺寸统一 |
| 底栏 | 频道、收藏、最近；图标和文字，清晰的选中状态 |
| 收藏／最近 | 双列卡片，显示频道名称及所属源；最近按观看时间由近到远排列 |
| 播放页顶部 | 返回、频道名称、收藏状态 |
| 播放页视频 | 完整显示画面比例，黑色背景；点击显示／隐藏必要控件 |
| 下方面板 | 频道／遥控器标签，支持点击及左右滑动切换 |
| 频道面板 | 当前源的分组选择与紧凑频道列表，标识当前播放频道 |
| 遥控器 | 大尺寸圆角上下台、音量增减按钮及音量显示；音量可用滑杆呈现 |
| 源管理 | 源名称、类型、频道数、当前源状态、管理操作与添加主按钮 |
| 设置 | 简洁列表，统一图标、开关及操作反馈 |

## 4. 功能需求

### 4.1 直播源导入与管理

**订阅链接**

- 输入源名称及频道列表地址。
- 支持 M3U/M3U8 频道列表、TXT 列表，以及使用兼容格式的 APTV 订阅。
- 解析后展示频道数、分组数，由用户确认导入。
- 重复订阅链接提示已有源，可选择刷新已有源。
- 地址下载失败、返回非列表内容或完全无法识别时，不创建空源。

**本地文件**

- 使用安卓系统文件选择器导入 M3U/M3U8、TXT 频道列表。
- 自动识别格式，默认用文件名作为源名称，允许修改。
- 展示解析结果后确认导入。

**手动频道**

- 必填频道名称、直接播放链接，可选分组。
- 提供已有分组选择及新建分组入口；未选时归入“未分组”。
- 统一保存到固定的“自建频道”，不写入订阅源。
- 支持后续编辑名称、链接、分组及删除。

**导入兼容**

- 区分频道列表地址与单频道播放地址，不只根据 `.m3u8` 后缀判断。
- 保留频道名、分组、台标、频道标识和必要播放请求头。
- 支持样本中出现的 User-Agent、Referer、`#EXTVLCOPT` 信息；未知扩展与注释不应导致整个文件失败。
- 完整保留播放 URL 查询参数，支持 HTTP/HTTPS 和无媒体扩展名的地址识别。
- 部分条目无效时允许导入有效频道，并显示跳过条数。
- APTV 专有标记不自动覆盖 Tunvix 的截图策略，不承诺兼容全部 APTV 专有功能。

**多源维护**

- 各源独立保存频道及分组，用户手动切换。
- 启动时读取本地保存的列表，不自动刷新订阅。
- 手动刷新只更新目标源；失败保留原列表，成功后保留可匹配的收藏和历史。
- 本地源通过重新导入更新，自建频道通过编辑维护。
- 删除源前确认影响，同时删除所属频道、截图、收藏和观看记录，不影响其他源。
- 删除当前源后切换到其他可用源；无剩余频道时显示添加入口。
- “自建频道”源本身保留，频道可以逐条删除。

### 4.2 浏览、搜索与频道操作

- 频道页展示当前直播源，支持分组和频道名称搜索。
- 搜索不修改原分组顺序和遥控器切台顺序。
- 收藏与最近汇总各源，记录必须关联所属源，不能仅凭同名合并。
- 所有卡片长按支持收藏／取消收藏。
- 自建频道额外支持编辑与删除；订阅／文件频道通过刷新或重新导入维护。
- 最近观看支持移除单条记录；取消收藏及移除记录直接生效。
- 删除自建频道需要确认；播放页提供收藏按钮。

### 4.3 播放与遥控器

- 默认竖屏，视频保留原始比例，不拉伸或强制裁切。
- 点击视频显示／隐藏播放暂停与全屏操作；直播不显示点播进度拖动条。
- 下方点击频道直接切台；面板切换不重新加载当前直播。
- 上下台按当前源、当前频道分组的列表顺序切换，首尾循环；只有一个频道时保持当前频道。
- 从收藏／最近进入时恢复该频道所属源与分组的切台上下文。
- 遥控器调节手机媒体音量，手机侧面音量键操作同步反映到界面。
- 手机媒体音量达到上下限后不能继续越界。

**横屏全屏**

- 点击全屏按钮手动进入，不通过日常旋转自动进入。
- 保持画面比例，提供退出全屏、频道名称、播放暂停、上下台及音量操作。
- 控件可隐藏，触碰画面后显示。
- 退出恢复竖屏、原面板与当前频道；转换不重新连接直播。

**生命周期**

- 返回频道首页停止播放并释放资源。
- 切到其他 App 或锁屏暂停，并停止拉取直播数据。
- 回到仍打开的播放页恢复当前频道，回到直播位置。
- 用户手动暂停与系统离开暂停应区分，避免恢复页面时覆盖主动暂停意图。

### 4.4 截图与流量

- 首页显示静态截图，优先读取已保存图片，不运行多频道动态预览。
- 当前分组缺少截图的频道在 Wi-Fi 或移动网络下自动补图，最多同时抓取 3 个，单频道总超时 8 秒，失败跳过继续。
- 成功截图持久保存在本地；滑动、切分组和重启不改变或重新抓取已有截图。
- 首页刷新更新当前分组截图；刷新时显示旧图，成功后替换，失败保留旧图。订阅更新仅让播放地址或请求头改变的频道截图失效。
- 当前频道播放、应用后台时停止额外截图任务。
- 无截图或获取失败时显示台标，再回退占位；失败不阻止用户播放。
- 截图最大 320×180、JPEG 质量 65。移除 24 MiB 磁盘自动淘汰，应用内存图片缓存上限 12 MiB。
- 删除源/频道同步删除对应截图；清理只删除截图，不删除源、收藏和观看记录。

### 4.5 失败与反馈

| 状态 | 界面与行为 |
| --- | --- |
| 首次无频道 | 添加直播源主按钮及简短引导 |
| 搜索无结果 | 无结果提示及清除搜索入口 |
| 连接中 | 加载动效与“正在连接”，允许返回和切台 |
| 暂时断流 | 有限自动重试，不自动跳到下一台 |
| 连续失败 | 停止自动重试，显示原因、“重试”“下一台” |
| 可能链接过期 | 订阅频道提供刷新所属订阅入口，不宣称已确定过期 |
| 订阅刷新失败 | 可理解的错误提示，保留旧列表 |
| 部分导入成功 | 有效频道数及跳过条数 |
| 无法导入 | 说明下载或识别问题，不创建空源 |
| 截图失败 | 台标或文字占位，仍可播放 |
| 收藏／最近为空 | 简短空状态，引导返回频道浏览 |

快速切台时，旧请求返回不能覆盖新频道的画面、错误提示或选中状态。

### 4.6 设置

设置内嵌在管理一级页，顺序为：移动网络播放提醒、按键震动反馈、显示首帧耗时、截图存储、清空观看记录、关于 Tunvix。

- 移动网络播放提醒：支持重新开启。
- 按键震动反馈：开关。
- 显示首帧耗时：默认关闭并持久保存；开启后频道、收藏、最近的缩略图右下角显示半透明深色小标签，数值按耗时分档着色（≤ 1000 ms 绿、≤ 3000 ms 黄、> 3000 ms 红，超时/失败红，未检测/检测中灰）。采用首次检测＋手动更新，结果与测量时间持久保存，播放地址或请求头变化后失效；检测与截图共享 3 并发名额和 8 秒总超时，纯检测不替换已有截图。
- 截图存储：占用空间与清理操作；清理仅清除图片，不清除耗时测量结果；Wi-Fi/移动网络均可补图。
- 清空观看记录。
- 关于 Tunvix：版本号。

## 5. 非功能要求与数据

- 直播源、频道、收藏、最近观看和用户设置在本地持久保存，重启后可用。
- 不需要后端账号或远程数据库服务。
- 视频播放优先于截图、解析及其他后台任务，不因大量频道导入阻塞主要操作。
- 表单适应长 URL、中文名称与软键盘，主要提交操作可到达。
- 示例频道和截图只用于视觉展示，不打包为内置直播源。
- 日志避免输出完整令牌或敏感播放地址；分享排查信息时隐藏相关参数。
- 更新 APK 的数据兼容、签名和迁移策略在实施方案中确定。

最小数据概念包括直播源、分组、频道、收藏、观看记录、截图缓存及设置。频道需保留所属源、名称、播放地址、分组、台标、可用频道标识及必要请求头；具体数据库结构不由本 PRD 固定。

## 6. 设计与开发交付

### 6.1 视觉交付

用户将委托 GPT 生成视觉设计。本文件作为设计输入，不要求 Codex 生成概念效果图。

需要覆盖频道首页、收藏、最近、播放页两个面板、横屏全屏、源切换、源管理、三种添加方式、导入结果、自建频道编辑、设置，以及必要空状态、错误状态、菜单和确认框。

### 6.2 技术方向

建议使用原生 Android：Kotlin + Jetpack Compose + Media3/ExoPlayer，以 Android 窗口安全区域机制实现系统栏融合。`minSdk = 29`；其余 SDK、构建工具、依赖版本与存储方案在实施计划中锁定。

环境准备和真机连接记录见 [产品需求讨论稿](Tunvix-产品需求讨论稿.md)。环境构建验证不等于产品播放或最低版本验收。

## 8. 实施前需锁定的细节
